# 共通配信台帳：確定ルールと実装状況（2026-11-07）

> **確定仕様の最優先参照先:** [`FOUR_LEDGERS_CANONICAL_SPEC.md`](./FOUR_LEDGERS_CANONICAL_SPEC.md)。この文書中の古い監査記述・旧コードの動作は、確定仕様を上書きしません。


## 確定した仕様（変更時は事前相談）
- 配信情報は **movie/tv + TMDB ID ごとに一件**。作品詳細と見る順番は同じ情報を読む。
- 日本国内の見放題・レンタル・購入だけ保存。見る順番ページはそのうち見放題だけ表示。
- 見る順番に掲載された作品は、**日本時間の毎朝6時にサイト側が自動で取得・保存する（訪問者のアクセスを待たない）1日1回**。夕方18時更新は旧方針。
- 見る順番対象外は、最終成功取得から24時間経過後の次回アクセス時に更新可能。
- 同一作品が複数シリーズに載っても配信データは一件。所属シリーズIDは重複なしで記録。
- 作品詳細からアクセスしても見る順番対象の作品に24時間更新を別途走らせない。
- 更新失敗時は前回成功データとその最終成功日時を保持。取得失敗を成功として記録しない。
- 作品詳細は最終成功取得日時と次回更新可能日時を表示する。
- Redis書き込み停止中は新規・既存を問わず保存更新しない。本番移行・書き込みは別承認。

## 実装済み（開発ブランチのみ）
- `vercel.json`: 既存の見る順番更新Cronを `0 21 * * *`（UTC 21時 = 日本時間毎朝6時）に変更し、旧18時実行を外した。
- `api/update-streaming.js` と `api/streaming-status.js`: 旧6時/18時の2窓を毎朝6時の1窓に統一した。現行 `doko:watch:v3:` を使う**暫定的な旧キャッシュの時刻修正**であり、共通配信台帳への一本化ではない。

- `api/_provider-ledger-policy.js`: 作品IDの正規化、シリーズ所属IDの重複排除、6時JST更新窓と24時間更新の判定、日本の配信データだけを選ぶ正規化。
- `tests/provider-ledger-policy.test.js`: 上記ポリシーのオフラインテストコード。

## 未実装・要検証（実装済みと混同しない）
- **共通配信台帳へ一本化した上で、毎朝6時JSTのCronから共通配信台帳を自動更新する接続を実装・検証する。** 既存Cronの時刻だけは開発ブランチで修正済み。現在の `api/_provider-ledger-policy.js` は時刻判定だけで、自動実行機能はない。
- 既存の `api/_detail-providers-cache.js` と見る順番の旧キャッシュを共通の保存先に接続する。
- シリーズ掲載・解除時に所属IDを正規台帳へ同期し、掲載漏れを防ぐ。
- 最終成功日時・次回更新可能日時の実際の表示を接続する。
- 旧キャッシュからの移行、競合・ロック・更新失敗時のテスト、旧キーの安全な整理。
- 本番Redis・TMDB・Vercelへの接続やデプロイは未実施。

この文書を配信更新仕様の参照元とし、旧6時/18時方式や「6時以降の初回アクセスで更新」を見る順番の新仕様として再提案しない。
