# 本番移行前に、利用者が見る画面

2026-11-09。今回は確認場所の案内だけです。こちらから本番へ接続したり、設定を変更したりしていません。画面名は表示言語・権限・契約によって違うことがあります。見つからない項目は「未確認」で構いません。

まずは下の3種類のメモがあれば、次の見積もりを進められます。金額・件数・単位・画面の日付だけで十分です。接続用の鍵、パスワード、支払カード情報は送る必要がありません。

## 1. Redisの保存量と契約

Upstashの管理画面で、現在サイトが使っているデータベースを選びます。Vercelの「Storage」「Integrations」から接続先が分かる場合もあります。新しいデータベースを作ったり、接続を追加したりする必要はありません。どれがサイト用か分からない場合は推測で選ばず、その点を未確認にします。

| 見る場所の目安 | 確認してほしいこと |
|---|---|
| データベースの概要/Usage（使用状況） | 今どれだけ保存しているか、上限はいくつか。MB/GB等の単位と、表示の日時 |
| 使用状況の回数の欄 | 今月の通信/操作数と上限。1日表示なのか今月表示なのか |
| データ送信量/転送量の欄 | 今月どれだけ外へ送ったかと、追加料金なしの上限 |
| Plan/料金・Billing（請求） | 無料、定額、使った分だけ払う契約のどれか。枠を超えると停止するか、自動で料金が増えるか |
| 同じ保存先の利用状況 | 別のアプリも同じ保存場所を使っているか |

分かる範囲で、容量が一杯のとき古い内容が自動的に消える設定なのかも確認対象です。分からなければ、その項目だけ後で確認します。データ一覧の大量表示、全件書出し、契約変更、削除はこの確認のために行わないでください。

## 2. Vercelの使用量・契約と公開中の版

Vercelで「ドコデミレル？」のプロジェクトと、それを所有するチーム/個人の画面を開きます。

| 見る場所の目安 | 確認してほしいこと |
|---|---|
| Usage（使用状況） | 今月の処理の呼出し数、処理に使った時間/量、送信データ量。表示される上限と日付範囲 |
| Settings/Functionsなど | 1回の処理を続けられる上限時間。見つからなければ未確認でよい |
| Billing/Plan（請求・契約） | プラン名、追加料金の条件、支払上限を超えたときの動作 |
| Spending/予算・通知の欄 | 上限で実際に止まるのか、お知らせだけなのか |
| Deployments（公開履歴）で現在のProduction表示 | 今公開されている版の日時と、表示されれば枝/版の識別情報。開発版1e647c8が未公開なのは予定どおり |

ページからの1回の処理の中でRedisと何度か通信します。「Redisの通信回数」と「Vercelの処理呼出し回数」は違うので、両方の画面を別々に確認します。再公開、公開先の切替、設定保存、支払上限の変更は不要です。

## 3. 自動更新がいつ、どこから起動しているか

Vercelのプロジェクト設定で「Cron Jobs」「定期実行」に相当する欄を見ます。

- 登録されている更新の行数と、対象の処理名/時刻。
- 最近の実行記録があれば、実際に動いた時刻と、成功/失敗したか。
- 時刻が世界標準時か日本時間か。コードにある世界標準時21時は、翌日の日本時間6時です。
- GitHubのActionsや別のサービスからも、更新を呼んでいないか。手動で更新する入口があれば、それもメモします。

資料には旧6時/18時という記載がありますが、現在の開発ブランチ内の設定は6時相当の1件です。本番で本当に何本動いているかは、実画面/実行記録を見ないと分かりません。この違いがあっても今すぐ設定を消さず、まずメモします。

通知の候補先（メール等）を決めるのはこの後です。既存の契約内で使えるか、追加料金があるか、更新が起動しなかった場合にも気付けるかを確認してから接続します。今回は送信しません。

## 4. 後で、公開前に見ていただく画面

実データで作った隔離プレビューが用意できてから、現在のサイトと見比べます。今回は実データのコピー不足のため、全情報一致の確認を依頼できる段階ではありません。

| 画面 | 見るポイント |
|---|---|
| 鬼滅の刃と配信サービス比較表 | 同じ作品の配信が一致するか。順番・文章・専用表示が変わっていないか |
| 他12シリーズ | 特集の順番/紹介/ポスター/タブを保っているか |
| 手動修正した作品・確認済み作品 | 題名や文章が戻っていないか。固定した項目が自動更新されないか |
| 複数監督や出演者の多い詳細 | 人が消えたり、役名/画像/関連作品が減っていないか |
| 人物検索・人物ページ | 同名人物を取り違えず、出演作や独自の分類/紹介が保たれているか |
| 全期/特番のあるTVと話一覧 | 期・話・特番の抜け、件数や日付の違いがないか |
| 検索の続き、PC/スマートフォン | 次のページへ進めるか。重複/抜け/表示崩れがないか |
| 作品の最初の表示・共有時の題名/画像 | 題名/説明/画像とURLが意図どおりか。既存特集の内容を上書きしていないか |

配信の「まだ分からない」「取得に失敗した」「前の正常情報」「正常に確認して0件」を区別できることも確認します。

## メモ用の書式

```text
Redis：保存量 __ / 上限 __（単位 __、表示日 __）
Redis：今月の回数 __ / 上限 __、送信量 __ / 上限 __
Redis：契約名 __、超過時は 停止 / 自動課金 / 未確認
Redis：他アプリとの共用 あり / なし / 未確認
Vercel：契約名 __、今月の処理量/送信量と上限 __
Vercel：処理1回の上限時間 __、料金上限は 停止 / 通知だけ / 未確認
現在公開中の版/日時 __
自動更新：起動元 __、行数 __、時刻/時間帯 __、最近の成功/失敗 __
```

スクリーンショットを使う場合も、鍵や支払情報は隠してください。データ本体の取り出し方と費用は、これらの確認後に別途相談します。現在の画面や契約が確認できない項目は、未確認として残します。
