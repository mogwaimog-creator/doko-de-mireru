## Commandsの数え方と削減方法

[Upstash公式の課金説明](https://upstash.com/docs/redis/overall/billing)で、EVAL本体に加えて内部のredis.call/pcallも計上、パイプラインは各命令、MULTI/EXECもそれぞれ計上と確認した。通信のまとめだけで課金命令数は減らない。公式ルールの確認と、実契約での計測は別であり、後者は未実施。書き込みの複製先がある場合の追加計上も未確認。

新方式では各キーをDUMP＋PEXPIRETIMEの2命令で保存する。型はDUMPに含まれるので、TYPEはPCの隔離Redisで調べる。Luaを使わない。キー名・値はバイナリのままBase64で保存し、ファイル・各値のSHA-256も保存する。期限なしは維持し、期限付きは絶対時刻で保存する。自然に期限切れになったキーは記録し、失効したデータを復活させない。

PCでは全DUMPを一時クローンへ復元して型と全バイトを検証し、さらに別の空の名前空間へ元の絶対期限を使って全件復元・照合する。文字列は件数32件とバイト量に上限を設けたMGET、その他は各DUMPで照合。各キーの期限は省略せず確認する。先頭や件数だけの照合ではない。全対象にEXISTSの事前確認を行い、RESTOREにREPLACEを付けず、既存キーを上書きしない。送信前にパイプライン全体の命令予算を予約し、失敗・応答消失時に自動再試行しない。

**実装はloopback専用で、実Upstash用の接続・削除・初期化機能を持たない。** 将来の本番復旧で使う元キー名への復元アダプターは未接続。現時点では本番実行可能な完成品ではない。
