## 複数ワーカーと障害時の停止

- 内容更新は30秒の所有トークン付き共有leaseを取得し、取得期限は6.5秒。取得中の別ワーカーは上流取得をせず、保存済み値/処理中状態を返します。人物と、同じTVのマニフェスト/話更新をそれぞれ共通キーで直列化します。
- 更新前の再読み取りに加え、**保存Lua内でも所有者・残りlease・CAS revision・手動ロックを検査**します。期限切れの旧ワーカーは新所有者のデータを保存/解除できません。取得期限を過ぎた遅い成功も無視します。
- 人物の初回取得失敗でもメタ情報を保存して暫定30分抑制します。既存成功がある場合は値を保持します。空/部分的なシーズン再取得による保存済みシーズンや話の消失は拒否します。
- 内容保存の通信障害は上流の取得失敗と混同せず、`storage-error`で停止します。新しいローカル制御キーに共通停止状態を保存できた場合は、別ワーカーも取得前に停止します。**この停止状態は自動解除しません。** ストレージ/保存結果を確認後、管理者が別途復旧を判断する設計です。停止状態の閲覧関数はありますが、解除UI/運用ツールは未実装です。
- 停止フラグ自体も保存できない完全な通信断では、全ワーカーへの停止伝達を保証できません。新規取得はlease/保存済み値の読み取りに失敗すれば始めませんが、既に開始した取得をネットワークの先で完全に取り消す保証はありません。この限界と実Redisの障害モードは本番前に確認が必要です。
