# 4台帳の最小構成・静的監査（2026-11-07）

対象: 開発ブランチ `work/four-ledgers-20261107`。静的監査と開発ブランチでのコード修正。本番Redis・TMDB・Vercelへの接続なし。

## 引き継ぎの最優先ルール（ユーザー指示）
- **決定事項・進捗・未完了・禁止事項は、ユーザーに再度依頼されなくても、その都度引き継ぎ書へ反映する。**
- 作業再開時には引き継ぎ書と確定仕様を先に読み、古いコードや過去の要約を優先しない。
- 決定済み事項を新提案として繰り返したり、再承認を求めたりしない。変更が必要な技術的理由があるときだけ説明して相談する。
- **見る順番掲載作品の配信更新は毎朝6時JSTを基準に1日1回**。6時/18時は廃止された旧方針。詳細ページと見る順番は共通配信台帳の同じ1件を参照。その他の作品は最終成功取得から24時間経過後のアクセス時更新。詳細は `docs/provider-ledger-single-source-policy.md`。
- TMDBの元の詳細応答を丸ごとRedisへ保存しない。必要なフィールドのみ抽出する。作品台帳の `extensions` は削除済みだが旧キャッシュの依存コードは未修正。
- 作品台帳の `seasons` は削除予定。作品詳細の上部のシーズン数と下部の各シーズン案内は、どちらもシーズン台帳を参照して維持する。
- 開発ブランチのコード更新と本番運用を混同しない。既存Redisの変更、移行、公開は別承認。


## 作品台帳
- `api/_work-ledger.js` に正規キー `movie/tv + TMDB ID`、`pageExtras` がある（`extensions` は作品台帳スキーマから削除済み）。ページ別の追加項目は可能。
- `api/_detail-metadata-cache.js` は `extensions.tmdbDetail` にTMDB詳細応答の大部分を保存する。`watch/providers` は除外するが、**共通フィールドに加えて元の詳細データも保持するため、最小容量化は未完了**。
- `WORK_LEDGER_ENABLED` と `LEDGER_WRITES_RESUME` による制御あり。既存レコードに `tmdbDetail` がなければ自動上書きせず修復エラー。

## 人物台帳
- `api/_person-ledger.js` の `compactPerson` は出演カードから `overview`、`original_title`、`popularity`、`vote_average` を除外する。
- プロフィール情報は保持。追加項目を自由に保存する専用拡張欄は、このファイルでは確認できない。
- 60日更新、書き込み停止時は既存値を読み取り、新規保存しない。

## 配信台帳
- `api/_detail-providers-cache.js` は日本の `results.JP` のみ保存。詳細ページはオンデマンド、保存後24時間を目安に再確認。
- 既存の「見る順番」ページの旧6時/18時更新とは**別のキー・別の更新方式**。これは旧実装の説明であり、新しい確定方針ではない。共通配信台帳への統合は未完了。
- 書き込み停止中でも、**既存の配信レコードは更新時にSETされ得る**。新規未保存データは保存しない。現行の凍結仕様を変更する場合は要相談。
