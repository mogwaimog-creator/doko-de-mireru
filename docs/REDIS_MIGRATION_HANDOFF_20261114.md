## 重要：移管前と移管後は別仕様
### A. 現在、移管完了までの緊急運用
1. 作品台帳に既存レコードがあれば、その保存済みデータを表示。
2. 作品台帳に未登録なら、**TMDBから直接取得して作品詳細を正常表示**する。
3. この直接取得結果は、上限間近の**旧Upstash作品台帳には新規保存しない**。
4. 旧Upstashの余計なコマンドが増えないように実装。急激にコマンド数が増えた場合は停止する。
5. 「台帳にないから作品詳細が503エラーになる」現状を解消することが優先。
6. この動作は移管前だけの暫定対応。恒久的な台帳未保存方式にしない。

### B. 新Redisへ移管完了後の通常運行
1. 作品台帳に既存レコードがあれば、保存済みデータを表示。固定情報・ロック・手動項目を維持。
2. 未登録作品はTMDBから新規取得し、**新Redisの作品台帳に保存**。以後は保存済み情報を使う。これが本来の確定仕様。
3. 人物・シーズンなど、一時停止していた機能は移管・テスト後に再開。
4. 配信台帳は日本の見放題・レンタル・購入を保持。13シリーズの配信更新は毎朝6時JST、通常作品は最終取得24時間後の次回アクセスで更新。失敗時は前回成功情報を保持。
5. 作品台帳V2の固定項目・確認後ロック・pageExtrasの手動固定、人物台帳のコンパクト保存等、既存仕様を変えない。

## 移管先候補・選定経緯（再質問を避けるための確定記録）
- 比較済み候補：Redis Cloud Free（容量約30MB、非アクティブ時の扱いに懸念）、Layerbase（RESTリクエスト約2,000回/日の制限が懸念）、Aiven for Valkey（無料枠約1GB RAM・月間コマンド数の公開上限が見当たらない点が魅力）。
- **移管先の第一候補はAiven for Valkey**。別候補の比較を最初からやり直さず、まずAivenで進める。上記の無料枠・制限は以前の比較に基づく概数であり、契約時点の公式条件・接続可否・利用可能地域・TLS/Lua互換性・無料枠を最終確認する。Aivenアカウントの作成・新DBの実稼働はまだ。
- AivenはValkeyのTLS/TCP接続であり、現行のUpstash REST（HTTPS POST + Bearer Token）とは**接続方式が違う**。作品台帳や更新仕様の作り直しではなく、Redis接続アダプターの切り替えで対応する。Lua/EVALとキー名前空間の互換性を検証する。
- Aivenが無料・互換性・安定性の要件を満たさないことが判明した場合のみ、理由を提示して移管先を再相談する。勝手に有料プランを選ばない。

## 実行工程（工程を変えずに引き継ぐ）
**第1段階：現在の表示復旧（移管とは別の緊急対応）**
1. Codexで、保存済み作品は台帳から、未登録作品はTMDBから直接表示する暫定修正をテストブランチで実装。
2. 旧Upstashに新規作品を保存せず、余分なRedisコマンドを増やさず、作品詳細のHTML/JSONが正常表示されることを検証。
3. Codex結果をChatGPTに共有してレビュー。本番公開は事前確認後、必要最小限のデプロイで実施。
4. 公開後のコマンド数を監視。急増時は暫定処理を停止。

**第2段階：Redis移管・通常運行への復旧**
1. Codexへ移管専用の更新済み指示を渡す。既存の作業ブランチを引き継ぎ、接続アダプターと移管テストを行う。
2. Aivenの最新の無料条件を確認し、ユーザーが必要なアカウント/サービス作成を行う。認証情報はチャットに貼らず安全な環境変数で扱う。
3. 旧Upstashの最新データを安全にバックアップ。コマンド残量と移管手段を見積もり、既存データを欠落させずに新Redisへコピー。元データは残す。
4. ローカル/隔離環境でLua、作品/配信/人物/シーズン台帳、SEO、13シリーズ、6時Cron、24時間更新、失敗時の保持、未登録作品の新規保存を検証。
5. テスト後に本番接続先を切り替え、一時停止設定を必要に応じて解除。旧Upstashへの通常アクセスが止まったことを確認。
6. main統合・本番デプロイ・公開動作確認。余計なデプロイを避け、問題時は切り戻す。
7. SEO二重取得最適化や過剰コマンドの根本原因の深掘りは今回の移管を妨げないよう別課題とする。
