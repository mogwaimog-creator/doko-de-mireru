# 人物台帳 v2 — 保存項目と4台帳の責務（開発用）

## 人物台帳に保存する項目（許可リスト方式）

人物レコード直下（4項目）：
- `schemaVersion`：保存形式の版
- `person`：人物プロフィールと出演作品
- `createdAt`：初回保存日時（更新時も維持）
- `checkedAt`：TMDBへの最終確認成功日時

`person` のプロフィール（9項目）：
- `id`, `name`, `original_name`, `biography`, `profile_path`
- `known_for_department`, `birthday`, `deathday`, `place_of_birth`

`person` の出演区分（5配列）：
- `cast`, `voice`, `directed`, `documentary_talk`, `other`

出演作品カード（各5項目）：
- `id`：TMDB作品ID
- `media_type`：`movie` または `tv`
- `title`：人物ページの表示名
- `year`：表示用の年（不明時は `null`）
- `poster_path`：人物ページのポスター表示用

上記以外の項目は人物台帳へ保存しない。項目を追加する場合は目的・利用画面・所属台帳を確認し、許可リストと検証テストを同時に更新する。

## 4台帳の役割
- **作品台帳**：作品の固定情報（作品名、公開年、ポスター、監督・キャスト等）。キーは `movie/tv + TMDB ID`。
- **配信台帳**：日本国内の配信可否、サービス、更新状況。人物台帳には保存しない。
- **人物台帳**：人物プロフィールと作品参照（`movie/tv + TMDB ID`）。配信情報、役名、評価、あらすじ、作品詳細、シーズン情報を保存しない。
- **シーズン台帳**：TV作品のシーズン固有情報。人物台帳には保存しない。

## 更新方針
- 初回アクセスで取得し、60日以内は保存済みデータを再利用する。
- 60日経過後は**次回アクセス時**に照合する。アクセスのない人物を一斉更新しない。
- TMDBの一覧取得後に保存済み一覧と比較し、変更を反映する。
- 変更がなくても確認日時 `checkedAt` の更新は必要。Redis書き込み回数はデモで検証。
- TMDB取得失敗時は保存済みデータを保持する。
- 古い人物台帳の一括削除・一括移行はしない。

## 2026-11-08 方針確定：出演作品は5項目を維持
- 現時点で人物台帳の出演作品をIDだけに置き換えない。
- 理由：共通作品台帳に未登録の作品も人物ページで表示できること、人物ページからの大量個別取得を避けることを優先する。
- 将来、容量・表示負荷の実測で必要になった場合に、共通作品台帳からの一括ID参照を検討する。
- 10作品の隔離デモでは、保存容量、表示速度、API呼び出し回数、未登録作品の表示を確認する。
- 管理画面・確認OK・手動ロック等は後回し。人物台帳を含む5台帳の準備後にまとめてデモを行う。
