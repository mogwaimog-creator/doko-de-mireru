- **本番デプロイなし、サイト全体の削減効果は未計測。**

## 残る重要課題
1. 固定情報の埋め込みは `extensions.tmdbDetail` というTMDB生データ。既存の `renderMovie` が期待するのは監督・出演・シリーズ等を加工した `/api/search` の応答で、互換ではない。
2. 初回アクセス削減には、生成時に**正規化済み固定応答**を作成して埋め込み、実行時に**配信差分のみ**取得する経路が必要。現行の分離APIは正規化済み固定応答を返せるが、これを呼ぶ時点で初回Function呼び出しが必要。
3. 配信差分だけを別Functionで取得しても初回のFunction呼び出しは1回残る。CDN Requests削減とTMDB/Redis負荷削減を区別し、増える通信・Function数を計測してから判断する。
4. 生TMDBからの正規化ロジックをブラウザへ複製すると仕様差分の危険がある。サーバー側の既存正規化処理を生成時に再利用できるよう切り出す案を優先する。
5. 作品詳細に付随するシーズン・シリーズ・人物等の別fetchは独立して監査する。6時/18時のCron・エラー表示・既存SEO URLは変更しない。
