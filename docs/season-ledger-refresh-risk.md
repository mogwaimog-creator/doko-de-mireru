# シーズン台帳：更新方式の設計課題（2026-11-07）

## 確認済み
- 新旧切替（OFF/ON、503、例外、初期化失敗）は模擬テスト合格。
- エピソード表示項目、クリック時の通信とエラー表示、TMDB風データはオフラインテスト合格。
- 本番デプロイ・本番Redis接続は未実施。

## 公開前に解決が必要な問題
現行のシーズン台帳は初回取得したレコードを Redis に `SET NX` で保存し、以降はキャッシュを優先する。保存期限も更新経路もない。このままでは、放送前のエピソード情報、放送日、タイトル、あらすじ、話数が後日更新されても、初回取得時の古い情報が残り続ける。

これはシーズン台帳が「初回取得して以降は固定」という仕様なら避けられない問題であり、作品固定情報・配信更新とは別に扱う必要がある。

## 推奨案（未実装・未承認）
- 放送中・放送予定のシーズンだけ、期限付きキャッシュまたは更新対象にする。
- 完結済みシーズンは長期キャッシュ。ただし訂正が必要な場合の手動再取得手段を用意する。
- 取得失敗時は直近の正常な保存内容を表示し、成功データを消さない。
- 更新時の競合制御、更新回数の上限、API負荷、Redis容量を別途テストする。
- `SET NX` による初回作成の安全性は維持し、更新処理は明示的な別ルートにする。

## 判定
**シーズン初回保存はオフライン検証合格。鮮度維持の設計が未確定のため、本番切替は保留。**
