# 作品詳細の静的化：実装直前の確認（2026-11-04）

## 現行実装で確認できたこと
- `api/search.js` の映画詳細は `metadataWithLedger('movie',...)` で固定情報を取得した後、`getDetailProviders('movie',...)` で配信を取得し、タイトル補正・配信・監督・シリーズなどを組み立てて返す。
- TV詳細も `metadataWithLedger('tv',...)` と `getDetailProviders('tv',...)` を使用し、アニメ判定、1話時間、シーズン表示などの変換を行う。
- `extensions.tmdbDetail` は **TMDBに近い生の固定情報** であり、`renderMovie` に直接渡せる**完成済みの画面用レスポンスではない**。これだけを静的に書き出しても現行ページの表示は再現できない。
- オフラインの固定情報抽出テストは成功したが、実際のRedis台帳の存在・件数・欠損状態は未確認。

## 実装の安全条件
1. 作品詳細APIの画面用レスポンス組み立て処理を、固定部分と配信依存部分に分割できるか検証する。現行のタイトル補正、アニメ判定、シリーズ構築、監督・出演者、レンタル・購入、FAQを維持。
2. 静的出力を生成する際は既存台帳の `extensions.tmdbDetail` の欠損を検知し、未完成ページを出さない。
3. 動的配信データの取得方法が確立する前に、ブラウザの `/api/search` を停止しない。現在の1回のAPIを2回に増やす案も採用しない。
4. 配信更新の6/18 Cron（シリーズ）と個別詳細の24時間キャッシュを混同しない。
5. 既存の公開URL、Vercel設定、Cron、セキュリティ対策を変更しない。

## 次に必要な検証
実際の台帳レコードを、秘密情報を出さない読み取り専用の方法で確認すること。現在のGitHubリポジトリのコードと試験用フィクスチャだけでは、Redis内の実レコードが揃っているとは断定できない。
