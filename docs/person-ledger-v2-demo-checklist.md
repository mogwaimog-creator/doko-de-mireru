# 人物台帳 v2 — デモ移行チェックリスト（本番変更禁止）

## 保存仕様
- 作品カードは `id / media_type / title / year / poster_path` の5項目だけ。
- 人物プロフィールは `prototype/person-ledger.js` の `PROFILE_FIELDS` に列挙された項目だけ。
- 管理情報は `schemaVersion / person / createdAt / checkedAt` の4項目。
- 不明な項目は自動保存せず、追加には仕様変更とテストを必要とする。
- `createdAt` は初回保存時刻を保持し、`checkedAt` は成功した確認日時を記録。

## デモの安全条件
1. 本番Redisを共有しない、独立したテスト用Redisまたは完全なメモリモックを使う。Previewというだけでは隔離にならない。
2. 本番の `doko:person:v1:` キーは読み書き・削除・一括走査しない。
3. v2 の書き込みを有効化する前にバックアップと復元テストを実施。
4. 旧レコードの変換は少数の匿名化したフィクスチャで検証し、本番の一括移行はしない。
5. 500作品を超える人物のカード欠落を防ぐため、上限仕様を解決する。
6. 作品カードの5項目、映画/TVリンク、プロフィール、5つの出演区分、60日経過後のアクセス時更新、取得失敗時の旧データ保持を検証。
7. 同一人物への同時アクセス、ロック期限、取得失敗、空レスポンス、日時の逆転、想定外フィールド混入を検証。
8. 旧データとの比較後に切替判断。公開反映はユーザーの明示承認後。
