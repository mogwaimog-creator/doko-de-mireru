# ④シーズン台帳 更新方針（開発ブランチ・本番未適用）

## 基本
- TV作品IDをキーにシーズン・各話を保存し、あらすじは保存しない。
- 上部のシーズン数・総話数と下部のシーズン一覧は同一の保存データから表示する。作品状態は作品台帳を参照する。
- 普段の閲覧は保存済みデータを返す。期限経過後の次のアクセスで更新対象を確認する。毎日全件走査しない。
- 放送中・続編予定・状態不明は7日間隔、放送終了を確認済みなら90日間隔を基本とする。ただし「放送終了」は必ずしも「今後の続編なし」を意味しないため、続編予定があれば7日側を優先する。
- 初回はTV作品のシーズン一覧を取得し、必要なシーズン詳細（各話番号・タイトル・放送日・時間）を取得する。あらすじなど不要な情報は破棄する。
- 更新時はまずTV作品の一覧・状態を確認し、新規・放送中・未完成のシーズンを優先する。完了済みの過去シーズンも定期的に再確認し、永続的に固定しない。
- TMDBはシーズンごとの変更通知を保証しないため、一覧が同じでも各話の変更を検出できるとは限らない。必要に応じて期限に基づく個別再取得を行う。
- 取得失敗時は旧データを保持。未取得・エラーを0話として表示しない。並行更新ロック・容量上限・タイムスタンプ保護をデモで検証する。
- 初回取得や更新で多数のシーズンがある場合は、API呼び出し上限と段階取得を設ける。部分取得を「全件取得成功」と記録しない。
- 作品台帳・シーズン台帳で同じTMDB作品詳細を重複取得しないよう、共有可能なデータ経路をデモで確認する。
- 10作品の隔離デモで表示整合性・API呼び出し回数・保存容量・更新判定・新規シーズン検知・既存シーズン再確認・失敗時挙動を確認する。
- PreviewのRedis隔離が確認できるまで書き込みフラグを有効にしない。本番切替は明示承認後。
