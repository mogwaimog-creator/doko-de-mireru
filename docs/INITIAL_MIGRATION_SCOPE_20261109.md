## 2. 共通情報は1作品1件、特集固有情報は別に保持

共通作品の識別は **映画/TV区分＋確認した作品ID** です。題名・年度だけで別作品を統合しません。同じ作品が13シリーズ・ジブリ・棚の複数に出ても、作品本体は1件にし、各特集の掲載情報から同じ作品を参照します。ID未確定・同名・複数版・区分不明は未解決一覧に置き、推測で新しい作品を作りません。

| 情報 | 保存/参照の方針 |
|---|---|
| 題名、原題、作品ID/区分、作品としての公開日、監督/出演者等 | 共通作品へ1件。手動修正・確認済み・項目ロックと出所を保護し、特集からの上書き合戦をしない |

| 映画賞 | 賞名、部門、対象年度/授賞年度、受賞等の区別、原文/出典/確認情報を棚の記録として保持。作品公開年へ機械的に寄せない |
| 興行情報・ランキング | 年、地域、集計区分、順位、金額/単位、配給収入/興行収入等の区別、合算対象、出典・確認情報を保持。日本/北米興行・キネ旬邦画/洋画を混ぜず、API人気順や評価点で置き換えない |

同じ共通作品に特集ごとの説明差がある場合は、共通情報と特集側の上書き表示を区別し、利用者が確認した見せ方を残します。別特集の手動情報が同じ旧作品レコードに同居していても、共通欄へ混ぜません。必要な共通の保護情報は維持し、範囲外特集の情報は原本へ残し、必要性を判断するまで新しい特集として有効化しません。

元の完全な値、ページ全体、確認/ロック情報、一覧順、データの出所を保存し、新旧比較で手動・確認・ロック・特集情報の差分0を開始条件とします。現在の作品変換の出演者8人/監督1人等の制限が、今回の保護指示を満たすと決めつけません。

## 3. 移行対象の3区分

### A：初期移行の必須対象

上の3対象の確認済み共通作品と、それらの特集固有情報。掲載に必要な配信・SEO等を関連付けて扱います。人物の全履歴を丸ごと取り込む許可ではなく、表示のために何が必要かを照合します。

### B：公開維持のために確認が必要な最小限の依存データ

現時点で報告すべき依存は次のとおりです。これらがあるため、A以外を「不要」として消す判定はできません。

| 依存 | リポジトリから確認した利用 | 移行前に決めること |
|---|---|---|
| 配信サービス比較表 | 13シリーズと同じ`/api/series-watch`を読む | 同一作品の配信値・正常時刻・未取得表示を一致させ、共有経路を保つ。表は追加保護対象ではなく必須対象を維持する依存 |
| トップの人気作品/ジャンル別一覧 | `index.html`に人気作品・ジャンル別のAPI読取りがある | 表示に必要な保存値や再取得への影響を確認。初期3対象だけの索引をサイト全体の一覧の代わりにしない |
| 通常検索・詳細・人物・期/話・SEO | 特集から詳細/人物へ、詳細から関連作品へ進む | どのID/表示項目が必須かを列挙。範囲外の作品へリンクがある場合は、原経路を保つか最小追加が必要かを報告 |

| 棚のポスター/詳細の補完 | `/api/search?id=...`または作品名検索を使う | 固定ID、合算行、別表記、補完に必要な保存値を照合。手動文章/受賞情報を補完結果で消さない |
| 棚への戻りリンク | `index.html`と`detail.html`から棚へ接続 | 対象年代・URL・戻り先を保ち、空の棚にしない |

人物ページの表示に出演リストを残す必要がある場合でも、そこに載る範囲外作品をすべて共通作品台帳へ登録する許可ではありません。旧読取経路や表示用の参照を保つ方法と、追加移行が本当に必要かを区別します。

一般検索・関連カードから必要範囲が無制限に広がることは許可しません。追加が必要なら「公開ページ/操作、欠ける表示、対象IDと最小件数、旧経路で維持できるか、追加容量/通信、代替方法」を示して報告します。未確認なら旧データを残して停止します。

`shelf-check.html`は公開APIでの一括検査用と書かれたページです。今回実行していません。通常表示の必須データと検査用の蓄積を同一視せず、本番での利用有無も未確認とします。

原則、新台帳・新索引・新しい互換コピーへ一括移行しません。選別根拠を作らずに全件をコピーしたり、移行対象外という理由で消したりしません。
