# 作品台帳・軽量実装の必須条件（2026-11-07）

## ユーザー確定方針（変更不可）
1. 決定済み設計を独断で変更しない。
2. 作品台帳は必要項目のみ抽出する**新しい軽量構造**。
3. 旧台帳の全件読出し・全件書換え・一括移行をしない。
4. 既存表示を維持するためローカルで表示用変換を検証。
5. 想定外の問題は別案を勝手に実装せず相談。
6. 本番Redisの変更・公開は明示承認後。

## 確認した既存コードと修正対象
- `api/_work-from-tmdb.js`: TMDBから共通フィールドを抽出する関数。現時点では作品・人物・配信・シーズンの分離と重複のない保存契約を全表示経路で検証できていない。
- `api/_work-ledger.js`: `normalizeWork` が共通フィールドと拡張欄を保持する。ページ別手動項目は `pageExtras`。正規キーは `movie/tv + TMDB ID`。
- `api/_detail-metadata-cache.js`: `fromTmdb` の結果に加えて `extensions.tmdbDetail` に詳細応答を保存。**新しい最小保存契約ではこの重複を新規作成しないこと**。既存Redis全件を書き換えるのではない。
- `api/search.js`: `metadataWithLedger` を利用する呼出元。既存の表示API応答の互換性を守る。

## 実装ゲート
- [ ] 既存映画・TV詳細のAPI応答と画面の使用フィールドをローカルで列挙
- [ ] ユーザーが決めた必要項目だけの保存形式と照合（項目追加は独断で行わない）
- [ ] 保存済み共通フィールドから旧API形式を生成する**純粋な変換関数**を作り、ローカルで検証
- [ ] 映画・TV・アニメ・シリーズ導線・人物リンク・配信表示の回帰テスト
- [ ] 既存の表示を維持し、元の詳細応答の二重保存をしないことをテスト
- [ ] 本番接続、容量、書き込み件数、切り戻しは事前承認の上で検証

## 作業上の禁止
- 本番Redisへの接続・書込み・全件スキャン・一括移行
- 旧データの削除や全件変換
- `WORK_LEDGER_ENABLED` / `LEDGER_WRITES_RESUME` 等の本番設定変更
- ユーザー承認前の本番デプロイ

この文書は作業制約の固定であり、保存スキーマの追加決定や本番改修を意味しない。
