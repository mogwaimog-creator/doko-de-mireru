# 運用時の取得・保存制限一覧（2026-11-11）
対象: 本番ブランチ `fix/detail-seo-route-20261110` / PR #26 適用後。
**障害調査では最初にこの文書を確認すること。** 数値はコードから確認したもので、環境変数やRedis管理状態の実値は別途確認する。料金上限とは別。

## TMDB外部取得
- 通常取得: **1分30件**、**1日 min(300, LEDGER_UPSTREAM_DAILY_LIMIT) 件**。設定値の実値は未確認。出典: `api/_acquisition-guard.js` ADMIT / `api/_release-connection.js`。
- 見る順番の定期取得（対象パス限定）: **1分300件・1日266件**。通常取得とは別枠。出典: `api/_acquisition-guard.js`。
- 同一リクエストの外部取得: 最大 **300回**。出典: `api/_release-source.js`。
- 外部取得が失敗した同一取得先: **5分間のクールダウン**が適用される場合あり（64バケットで管理）。出典: `api/_acquisition-guard.js`。
- 検索キャッシュ: **1時間**。64バケットの一時保存で競合し得る。PR #26 以降は検索キャッシュが busy/capacity のとき、既存の取得制限内で直接取得にフォールバック。その他のエラーは引き続き失敗。出典: `api/_recovery-fetch-cache.js`。
- 検索で一部の閲覧モード: 1リクエスト内の異なる取得先は **12件まで**。出典: `api/_release-application.js`。

## 新規作品・保存
- 新規作品取得: Redis管理設定 `newWorkDailyLimit` に達すると停止。**実際の設定値は未確認**。また `newWorkAcquisitionPaused` が真なら停止。出典: `api/_new-work-ingest.js`。
- 新規作品取得のタイムアウト: **6.5秒**。出典: `api/_new-work-ingest.js`。
- 管理対象の同時処理: **64件まで**。超過時は拒否。出典: `api/_acquisition-guard.js` ENTER。
- 一時保存の作品データ: 約 **20MiB** 上限。これは5台帳全体の保存容量上限ではない。出典: `api/_recovery-fetch-cache.js`。
- Redis管理キー `doko:dev:content-control:v1` が ready でない場合は、新規取得・更新が拒否されることがある。出典: `api/_acquisition-guard.js`, `api/_new-work-ingest.js`。
- VercelのBot Protection / Rate Limit / Spend Management等の**実際の設定値はこの文書では確認していない**。これらは上記のコード制限とは別。

## 障害時の最初の切り分け
1. 独自ドメイン `doko-de-mireru.com` が**修正版デプロイを指しているか**、VercelのAliasを確認。READYだけでは本番反映を保証しない。2026-11-11の検索復旧時、修正版がREADYでも独自ドメインが旧デプロイを参照していた。
2. 検索だけ失敗する場合: `api/_recovery-fetch-cache.js` の busy/capacity、`api/_acquisition-guard.js` の upstream-limit / failure-cooldown、Redis通信エラーを区別。
3. 未登録作品の詳細だけ失敗する場合: `api/_new-work-ingest.js` の daily-limit / acquisition-paused / lease / timeout を確認。
4. 既存作品の詳細が失敗する場合: `api/_release-application.js` の fixed/detail、作品台帳・TVシーズン台帳の読み取りを確認。
5. エラーを一律に握りつぶす `api/_release-dispatch.js` の catch に注意。ログに実際の例外が出ない可能性あり。
6. **5台帳と保存済み配信情報は保全**。調査のために削除・再初期化しない。
7. 変更後は修正版のデプロイ確認だけでなく**独自ドメインのAliasと実際の検索・詳細表示**を確認。
