## 目的（変更しない）
- 作品・人物・配信・シーズンをそれぞれ一元管理し、同じ作品の重複保存とTMDB・Redis・Vercelへの無駄なアクセスを減らす。
- 既存の映画・ドラマ・アニメ検索、作品詳細、人物詳細、12本の「見る順番」、特集、SEO表示を壊さず、表示を速くする。
- サイトの更新・新規作品追加が増えても、データは共通台帳から再利用する。
- 本番の追加課金や容量増加を招かない。公開・本番Redis変更・一括移行・削除は明示承認まで行わない。

## 1. 作品台帳（正規キー: movie/tv + TMDB ID）
- 作品ごとに共通固定情報を一件保存。作品名・原題・年/公開日・紹介・ポスター・監督・主要キャスト・ジャンル・時間・評価・シリーズ紐付け等、画面で必要な最小限のみ。元のTMDB詳細応答を丸ごと保存しない。
- 初回取得で自動入力できる範囲を作り、手動で作品ID・内容を確認したら「確認OK」にできる。確認OK/手動修正した項目は自動更新で勝手に上書きしない。エラーは専用欄に記録し、手動で直して確認OKとする。項目別のロック・誤上書き防止が必要。
- 「見る順番」「名作映画の棚」等への掲載は同じ作品を複製せず、所属・掲載箇所やページ専用の編集情報を追加する。専用編集欄は自動取得で上書きしない。無制限の任意データ・巨大な原文は保存しない。ページ専用情報は許可する項目を明確にして容量を抑える。
- シーズン詳細はシーズン台帳へ。作品のTV放送状況 `status` は作品台帳に残す。collectionIdは共通の紐付け用。シリーズ名はグループ側で共通管理。
- IDが違う作品を曖昧な作品名だけで混同しない。既存データの全件書き換えはしない。

## 2. 配信台帳（同じ正規キーで作品ごとに一件）
- 作品詳細と12本の「見る順番」は**必ず同じ配信台帳の一件**を読む。複数シリーズに載ってもデータを重複させない。
- **見る順番掲載作品は毎日日本時間06:00に、サイト側のCronが訪問者を待たず自動取得・保存する。** 旧06:00/18:00の2回更新も「06:00以降の初回アクセスで更新」も不採用。
- その他の作品は初回アクセス時に取得・保存。最終成功取得から24時間経過した後、**次のアクセス時だけ**配信を更新。何年アクセスがなくても自動巡回しない。
- 見る順番に追加した作品は06:00自動更新対象へ切り替える。詳細ページから開かれても独立した24時間更新を走らせない。シリーズから外れた作品は通常のアクセス時24時間方式へ戻す。
- 日本国内の見放題・レンタル・購入情報だけ保存。見る順番は見放題ロゴのみ、作品詳細は3区分を表示。最終成功日時・次回更新可能日時を適切に表示。
- 更新失敗時は前回の成功データと日時を保持し、エラーを記録。重複ID排除、並列数制限、ロック、時間制限、失敗分再試行を設ける。書き込み停止中は新規・既存とも書き換えない。
- 既存の `doko:watch:v3:` と `doko:detail-providers:v1:` は**旧・暫定キャッシュ**。一本化後の正式な二重運用はしない。

## 3. 人物台帳
- TMDB人物IDごとに一件。プロフィールと出演作品の必要最小項目のみ保持し、出演カードに配信情報や作品詳細全体を重複保存しない。
- 人物ページはプロフィールと出演作品を表示し、作品詳細へのリンクは共通作品台帳を参照。既存の約60日更新方針を維持し、閲覧のない人物の全件巡回はしない。
- 人物情報の初回保存・再利用・更新失敗時の旧データ保持を確認する。

## 4. シーズン台帳
- TV作品のシーズン情報を作品台帳から分離し、必要最小限を保存。エピソードの長いあらすじ等、不要な重複情報を保存しない。
- 作品詳細上部の「全5シーズン」「シーズン5まで」等の表示と、下部の各シーズン一覧は、どちらも同じシーズン台帳から生成する。既存表示を維持。

## 5. SEO・運用・保護
- 共通テンプレのままクローラーへ返さず、作品ごとの title / description / h1 / OGP 等を初回HTMLに反映できるようにする。少数作品で検証してから拡大。
- 更新成功・失敗と時刻を確認できること。失敗時に必要な手動確認ができること。手動編集・確認OK・ロックを保護すること。
- 月1回程度を目安にPCへ日付付きフォルダでバックアップを保管し、復元テストを含める。バックアップなしで削除・一括移行しない。
- 本番Redis・TMDB・Vercelへの書き込みや公開は事前承認。まず開発ブランチで静的確認・オフラインテスト・互換性検証。作業はまとめてテスト・デプロイ。

## 新作品台帳へ置き換えるための「データ・項目・運用」確定ルール（2026-11-06決定／11-07再確認）
**これは開発の進め方ではなく、置換後の作品台帳そのものが守る仕様。10作品の試作段階から適用する。**

### A. 共通作品データの保存項目（必要最小限）
- 正規キーは `type(movie/tv) + TMDB ID`。同じ作品は掲載先が複数でも**一件だけ**。
- 初回に自動取得する共通項目：TMDB作品ID、映画/TV区分、作品名、原題、公開日/初回放送日、ポスター、TMDB評価、上映時間、ジャンル、基本紹介、監督、出演者最大8名と各TMDB人物ID。
- TVの共通概要には放送状況を保持する。**シーズン数・総話数・各シーズンの情報はすべてシーズン台帳で一元管理し、作品台帳には保存しない。**
- TMDB評価の最終更新日を保持。**評価だけは1年以上経過した作品を順次更新**できる。ほかの確認OK済み・ロック済み共通項目や手動編集情報は更新しない。
- 配信情報は作品台帳に入れず、配信台帳で一元管理。TMDB応答全体、巨大な原文、重複した人物・シーズン・配信データを保存しない。

### B. 自動取得・確認OK・ロック・エラーの流れ
1. 未登録作品だけ必要項目を自動取得・抽出して仮登録する。登録済みなら保存済みデータを再利用し、**基本情報を毎回取り直さない**。
2. 確認OKになる前は内容・IDを人が確認し、必要な項目だけ手動修正する。
3. 正常なら**「確認OK」→共通基本情報をロック**。以後は自動取得で上書きしない。差異がなければそのまま長期利用する（評価の年次更新は上記の例外）。
4. 取得・検証でエラーが出た場合は作品の専用エラー欄へ記録し、同時にエラー一元管理一覧に表示する。人が修正・再確認してから確認OKとし、ロックする。通常作品もエラーの有無に関係なく定期的な人の確認後に確認OKとする。エラーを無視して自動確定しない。
5. 手動修正した項目、確認OK済みの基本情報、ページ専用欄は、通常の自動更新で変更しない。項目別ロックと確認OK後の全体ロックを実装・テストする。

### C. 掲載先・ページ専用情報の扱い
- 「見る順番」「名作映画の棚」などの掲載先は同一作品レコードに**所属参照を追加**して管理する。新しい特集が増えたら所属だけ増やせる。
- 掲載先固有の紹介・順番・一言・解説などは**後から手動入力**する。専用欄 `pageExtras` は手動固定で、自動取得に上書きさせない。許可した項目だけを保存し、無制限の追加を防ぐ。
- 既存の**12本の「見る順番」ページの作品名・公開年・ポスター・紹介文・独自解説・年表・デザインは維持**。移行を理由に一括上書き・全面自動生成しない。ページ独自の文章や配置は必要に応じて**HTMLベタ書きのまま固定**してよい。共通作品データは必要な箇所で参照し、配信情報のみ共通配信台帳に接続する方針を維持。
- 新企画のページ専用編集情報も、無理に自動化せず手動固定・ベタ書きを選べる。

### D. 旧データから新方式への置換・保全
- 既存PCバックアップ等から**新台帳に必要な項目だけを抽出・変換**する。旧台帳の余分な項目をそのまま持ち込まない。新方式の10作品検証→件数拡大→既存データ変換→接続の順。
- 古いデータは新方式での正常動作確認まで削除しない。本番への切替・Redisの書き換えは事前承認が必要。
- PCへ**月1回および大きな変更の前後**にバックアップを取得し、日付別フォルダに保管する。復元可能性を確認する。
- 既存ページは置換後も見た目・独自文章を守る。変更対象を共通データの読み出し・保存部分に限定し、試作を使い捨てず本番用に育てる。

### E. 試作で必ず検証する例外
- 確認OK後の再取得でも固定情報は変化しないこと。

## 確認OKとエラー一元管理の区別（2026-11-07修正確定・前記の曖昧な表現より優先）
- **新規登録作品は、エラーがなくても未確認状態で保存する。** 管理者が定期的に「未確認作品一覧」を確認する。自動取得が成功しただけでは確認OKにしない。
- **通常フロー:** 自動取得・仮登録 → 未確認一覧 → 人による作品ID・タイトル・ポスター等の確認（必要なら手動修正） → 「確認OK」 → 共通固定情報をロック。
- **エラーフロー:** 取得/検証/登録エラー → 当該作品のエラー欄に記録 ＋ エラー一元管理一覧に集約 → 手動修正 → 再チェック → 「確認OK」 → ロック。対応後はエラー一覧で解決済みとし、履歴は保持する。
- **二つの一覧は目的が違う。** 「未確認作品一覧」はエラーのない新規作品も含む定期点検用。「エラー一元管理」は異常をまとめて修正・追跡するためのもの。両方に該当する作品もある。
- **確認OKはエラー専用の操作ではない。** エラーがない新規作品でも必ず人の確認を経て行う。エラー未解決のまま確認OK/ロックしない。
- **10作品試作の必須テスト:** 正常取得→未確認→定期チェック→確認OK→ロック、およびエラー発生→二重記録（作品欄＋一元一覧）→修正→再確認→解決済み→確認OK→ロックをそれぞれ実行する。
