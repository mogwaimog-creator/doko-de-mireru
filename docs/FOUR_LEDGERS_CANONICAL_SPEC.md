# ドコデミレル？ 4台帳・確定仕様（最優先の引き継ぎ元）
更新: 2026-11-07 / 開発ブランチ: `work/four-ledgers-20261107`

> **この文書は確定した目的と実装状況を分離して記録する。古いコード・古いコメント・過去の6時/18時仕様と矛盾した場合は、この確定仕様を優先する。技術的理由で変更が必要なら、実装前に相談する。ユーザーに同じ決定を再確認しない。**
> **「実装済み」と記すには、該当コードへの接続と検証が必要。純粋関数や設計書だけで完了扱いしない。**

## 目的（変更しない）
- 作品・人物・配信・シーズンをそれぞれ一元管理し、同じ作品の重複保存とTMDB・Redis・Vercelへの無駄なアクセスを減らす。
- 既存の映画・ドラマ・アニメ検索、作品詳細、人物詳細、12本の「見る順番」、特集、SEO表示を壊さず、表示を速くする。
- サイトの更新・新規作品追加が増えても、データは共通台帳から再利用する。
- 本番の追加課金や容量増加を招かない。公開・本番Redis変更・一括移行・削除は明示承認まで行わない。

## 1. 作品台帳（正規キー: movie/tv + TMDB ID）
- 作品ごとに共通固定情報を一件保存。作品名・原題・年/公開日・紹介・ポスター・監督・主要キャスト・ジャンル・時間・評価・シリーズ紐付け等、画面で必要な最小限のみ。元のTMDB詳細応答を丸ごと保存しない。
- 初回取得で自動入力できる範囲を作り、手動で作品ID・内容を確認したら「確認OK」にできる。確認OK/手動修正した項目は自動更新で勝手に上書きしない。エラーは専用欄に記録し、手動で直して確認OKとする。項目別のロック・誤上書き防止が必要。
- 「見る順番」「名作映画の棚」等への掲載は同じ作品を複製せず、所属・掲載箇所やページ専用の編集情報を追加する。専用編集欄は自動取得で上書きしない。無制限の任意データ・巨大な原文は保存しない。ページ専用情報は許可する項目を明確にして容量を抑える。
- シーズン詳細はシーズン台帳へ。作品のTV放送状況 `status` は作品台帳に残す。collectionIdは共通の紐付け用。シリーズ名はグループ側で共通管理。
- IDが違う作品を曖昧な作品名だけで混同しない。既存データの全件書き換えはしない。

## 2. 配信台帳（同じ正規キーで作品ごとに一件）
- 作品詳細と12本の「見る順番」は**必ず同じ配信台帳の一件**を読む。複数シリーズに載ってもデータを重複させない。
- **見る順番掲載作品は毎日日本時間06:00に、サイト側のCronが訪問者を待たず自動取得・保存する。** 旧06:00/18:00の2回更新も「06:00以降の初回アクセスで更新」も不採用。
- その他の作品は初回アクセス時に取得・保存。最終成功取得から24時間経過した後、**次のアクセス時だけ**配信を更新。何年アクセスがなくても自動巡回しない。
- 見る順番に追加した作品は06:00自動更新対象へ切り替える。詳細ページから開かれても独立した24時間更新を走らせない。シリーズから外れた作品は通常のアクセス時24時間方式へ戻す。
- 日本国内の見放題・レンタル・購入情報だけ保存。見る順番は見放題ロゴのみ、作品詳細は3区分を表示。最終成功日時・次回更新可能日時を適切に表示。
- 更新失敗時は前回の成功データと日時を保持し、エラーを記録。重複ID排除、並列数制限、ロック、時間制限、失敗分再試行を設ける。書き込み停止中は新規・既存とも書き換えない。
- 既存の `doko:watch:v3:` と `doko:detail-providers:v1:` は**旧・暫定キャッシュ**。一本化後の正式な二重運用はしない。

## 3. 人物台帳
- TMDB人物IDごとに一件。プロフィールと出演作品の必要最小項目のみ保持し、出演カードに配信情報や作品詳細全体を重複保存しない。
- 人物ページはプロフィールと出演作品を表示し、作品詳細へのリンクは共通作品台帳を参照。既存の約60日更新方針を維持し、閲覧のない人物の全件巡回はしない。
- 人物情報の初回保存・再利用・更新失敗時の旧データ保持を確認する。

## 4. シーズン台帳
- TV作品のシーズン情報を作品台帳から分離し、必要最小限を保存。エピソードの長いあらすじ等、不要な重複情報を保存しない。
- 作品詳細上部の「全5シーズン」「シーズン5まで」等の表示と、下部の各シーズン一覧は、どちらも同じシーズン台帳から生成する。既存表示を維持。

## 5. SEO・運用・保護
- 共通テンプレのままクローラーへ返さず、作品ごとの title / description / h1 / OGP 等を初回HTMLに反映できるようにする。少数作品で検証してから拡大。
- 更新成功・失敗と時刻を確認できること。失敗時に必要な手動確認ができること。手動編集・確認OK・ロックを保護すること。
- 月1回程度を目安にPCへ日付付きフォルダでバックアップを保管し、復元テストを含める。バックアップなしで削除・一括移行しない。
- 本番Redis・TMDB・Vercelへの書き込みや公開は事前承認。まず開発ブランチで静的確認・オフラインテスト・互換性検証。作業はまとめてテスト・デプロイ。

## 作品台帳の開発方式：完成形を独立して作る（確定）
- **本番サイト・本番Redis・既存公開コードはそのまま維持**する。現行の仮台帳や旧キャッシュを延命・継ぎ足しする方式を採用しない。
- 開発ブランチ内に**既存ルートから切り離した新しい作品台帳の完成形**を作る。仮の項目・旧仕様・重複保存は新しい完成形には持ち込まない。削除は複製/新規実装の中だけで行い、本番・既存保存データは削除しない。
- 必要な固定情報、手動入力、確認OK、項目別ロック、エラー記録、関連作品ID、掲載先、ページ専用編集項目を**作品台帳単体で一通り完成**させる。関連作品は movie/tv + TMDB ID で参照し、本体を複製しない。
- サンプルデータと実際に操作できるテスト・検証用の入り口を用意し、初回登録、再取得、確認OK後の上書き防止、エラー修復、ID紐付け、保存・再読込を検証する。純粋関数だけでは完成扱いにしない。
- 作品台帳の完成形を先に固定し、その後に本番既存ページとの互換アダプターと安全な切替手順を準備する。配信・人物・シーズンの全面改修を同時進行しない。
- **最後に本番へ組み込む際は別途承認**を受ける。バックアップ・復元・切り戻しを準備し、既存表示を壊さず段階的に接続する。完成形の作成と本番公開を混同しない。
- 「後回しにした項目」が消えないよう、新作品台帳の完成条件は項目ごとの動作テストで管理する。旧コードに合わせて目的を変更しない。
